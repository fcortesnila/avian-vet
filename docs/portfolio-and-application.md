# Portfolio and application notes

Use this as a checklist and fill in only facts that can be substantiated. Do not present this starter as deployed, clinically validated, or used with real patients.

## Show AI product work

Describe the problem and user, the explicit non-goals, how the corpus is governed, how retrieval and citations work, how failures abstain, and which evaluation results changed the design. Include a short demo using synthetic patients and reviewed sample content. State clearly what is prototype versus production.

## Demonstrate delivery discipline

Link CI runs, test strategy, deployment architecture, staged release plan, monitoring, rollback path, and backup/restore evidence when these exist. A Terraform starter and Compose setup are foundations; they are not proof of a cloud deployment. Add a real deployment only after provisioning and validating it in an account you control.

## Address seniority with evidence

If production experience exists outside public repositories, surface it directly in the application and interview. Add concrete, verifiable examples:

- **Ownership:** [system/product], [your decision and scope], [team/stakeholders].
- **Scale and reliability:** [traffic/data/users], [availability/latency target], [measured outcome].
- **Delivery:** [incident, migration, launch, or operational improvement] and your role.
- **Leadership:** [mentoring, technical direction, review process, or cross-team work].
- **Evidence:** [references, sanitized artifacts, metrics, or public links that can be shared].

If there is no such experience, say so plainly and emphasize the closest truthful evidence. Do not imply that portfolio code represents employer production work.

## Suggested application paragraph (customize truthfully)

“My public portfolio does not show the full scope of my production work. At [organization/project], I [specific ownership], serving [users/scale] and improving [measured outcome]. I can discuss the design tradeoffs and operational lessons in detail. Separately, Avian Vet demonstrates how I approach an AI product lifecycle: explicit safety boundaries, inspectable sources, evaluation gates, CI, and a deployment path. It is a prototype and has not been clinically validated.”
